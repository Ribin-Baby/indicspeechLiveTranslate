Indic Live Translation Pipeline

Two people join a LiveKit call, each speaking their own language. An agent listens to every microphone, cleans the audio, recognises the words, translates them, and speaks the translation into a track only the listener receives, with live captions alongside. Calls currently use English and Hindi.

~1.3 sspeaker stops → listener hears (English → Hindi)
6 modelsnoise removal, end of turn, ASR, 2 translators, TTS
3 machinesthis VM + two GPU hosts

One sentence, end to end

What happens between Ben saying a sentence in English and Asha hearing it in Hindi. Every caller is a speaker and a listener at once; the agent runs this path for each of them.

  1. Speaker's browser

  2. Microphone to LiveKit

    browser → LiveKit

    The page captures the mic with the browser's echo cancellation, noise suppression and gain control, and publishes it over WebRTC (Opus). LiveKit forwards it to the agent.

  3. Agent: listening

  4. Echo cancellation

    agent · CPU

    The agent receives the mic at 16 kHz in 20 ms frames. WebRTC AEC3 removes anything the agent itself played into the room, using its own playout as the reference. An echo monitor finds the echo delay and switches the cleaned audio in only while playout is actually leaking into that mic. ~0 ms

  5. Background noise removal

    agent → Maxine BNR

    The audio goes up to 48 kHz, streams to NVIDIA's BNR model in 10 ms chunks over one gRPC stream per caller, and comes back down to 16 kHz. It removes fans, traffic and keyboard noise, and each caller can turn it off in Settings. If the model is unreachable or stalls for 0.5 s, the raw mic is used instead. ~13 ms round trip + 40 ms model lookahead

  6. Voice and end-of-turn detection

    agent · Silero VAD + Smart Turn, CPU

    Silero VAD scores each 32 ms frame. When a pause reaches 150 ms, the agent asks Smart Turn, an 8 MB model on the CPU, whether the speaker has finished. It judges from their last 8 s of words and intonation:

    • finished: the utterance ends at once, keeping 200 ms of padding;
    • unfinished: a short utterance waits up to 0.7 s for the rest, a long one the normal 0.35 s;
    • no answer: a 350 ms pause ends it;
    • a hard cut at 15 s in every case.

    ~0.15 s pause + ~60 ms model

  7. Speech recognition

    agent → Parakeet

    The whole utterance goes to Parakeet 1.1B (offline mode) in one HTTP request. While the person is still talking, the utterance so far is re-transcribed every 0.5 s for live captions. ~50 ms per request

  8. Echo check

    agent · CPU

    The agent compares the utterance's loudness with what it played into the room. A score of 0.72 or more is treated as echo and dropped, and so is 0.5 or more when the utterance repeats words that were just played. Otherwise it goes on.

  9. Agent: translating and speaking

  10. Translation

    agent → Qwen

    The utterance is translated once per listener language, all languages in parallel.

    • Qwen gets an interpreter instruction with thinking turned off.
    • A sentence end mark is added first, which stops it swapping names in unpunctuated text.
    • Its reply streams into the listener's captions as it's written.
    • Letters copied over in the wrong script are respelled.
    • Riva Translate can take over with one setting: about 0.3 s faster, but weaker Hindi → English.

    ~0.5–0.7 s for a sentence

  11. Speech

    agent → Magpie

    Magpie speaks the translation once per language, in the voice the speaker chose, streaming 48 kHz audio. Everyone hearing that language gets copies of the same audio. Magpie's silence before and after the speech is trimmed as it streams. ~50 ms to first audio

  12. Playback

    agent → LiveKit

    Each listener has a queue that plays translations in order, on their own track translation-<listener>. LiveKit permissions let only that listener subscribe to it.

    A translation that had to wait for the one before is sped up without changing the pitch: 1.06× after a 0.3 s wait, 1.2× at 1 s, up to 1.4×.

  13. Listener's browser

  14. Listener hears it

    LiveKit → browser

    The page plays the translation track. The speaker's own voice is muted by default, and a slider can mix it back in. Captions show the original words, the translation, its state and its delay. ~0.1–0.2 s WebRTC delivery

What each caller sets

These are LiveKit participant attributes. They're chosen on the join screen, can be changed in Settings during the call, and the agent applies a change from the next sentence.

AttributeValuesEffect
speakEnglish, HindiLanguage their speech is recognised in. A change restarts their recognition.
hearEnglish, HindiLanguage their translation track is in. If it matches the speaker's language, the page plays the speaker's own voice instead.
voiceFemale: Louise, Aria, Sofia, Isabela, Leo · Male: Jason, Pascal, DiegoThe voice the others hear them in. Grouped by measured pitch, because NVIDIA publishes no genders; defaults are Louise and Jason.
bnron (default), offBackground noise removal on their own microphone. A change restarts their recognition with or without it.

The agent sends JSON messages on the captions data topic to everyone in the room:

When something fails

  • Noise removal down or slow: that mic falls back to raw audio within 0.5 s; the call carries on.
  • End-of-turn model fails or answers late: the pause rules decide alone (a 350 ms pause ends the utterance).
  • A translation or voice request fails: it's logged and reported in the page's status, and the next sentence goes through normally.
  • The agent restarts or crashes mid-call: it leaves within 5 s. The web app's watchdog checks every 5 s and re-dispatches it to any of its rooms left without a translator for 8 s. Calls lose translation for ~10–15 s.
  • Echo: two devices in one room, or a loud speaker, can feed translations back into a mic. Echo cancellation and the echo check stop the translation from bouncing back and forth.
  • Sharing LiveKit with meetmind: the agent joins only rooms whose tokens ask for indic-s2s, and meetmind ignores rooms it doesn't know. Restarting meetmind's LiveKit drops calls in both apps.

Configuration

This repo's .env sets COMPOSE_FILE=docker-compose.yml:docker-compose.shared.yml, so docker compose up -d starts only the agent, the web app and the proxy, using the models above. Removing that line runs the repo's own model stack instead: IndicConformer, indic-translate and indic-speak, with 5 languages to speak and 23 to hear.
